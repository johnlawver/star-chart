# Devices connect outward to the server

An observatory's parts (screen, printer, scanner) always open their own connections out to the server, to collect print jobs and send hand-ins, and the server never reaches in to a device. That way an observatory works the same whether the server is on a home Mac mini, on Tailscale or in the cloud, with no port forwarding, which matters because Star Chart may become a hosted service. The long-term aim is for the parts to connect to each other locally, with only one connection to the server per observatory. For now each part connects to the server on its own, because we don't yet know what the screen hardware (probably a jailbroken Android picture frame) will let a web page do with a camera or printer. Either way, the server tracks which parts belong to which observatory, and if one part is offline the screen says so rather than holding work in a queue for later.
